# ChatGPT / GitHub Copilotのサブスクを使う

APIキーの代わりに、ChatGPTやGitHub Copilotのアカウントで校正することができます。設定画面では、ChatGPTの接続は「Codex（ChatGPT）」と表示されます。

この方法では、各サービスのCLIというソフトウェアを使って接続します。対応するCLIは設定画面からインストールできます。アカウントで使えるモデルや利用枠は、接続後に取得します。

## 接続する

1. JP Scratchの設定を開き、「契約サービス」を選んでください。
2. 使用するサービスの「CLIをインストール」を押してください。公式GitHubから約90〜140MBをダウンロードします。
3. 「ブラウザーでログイン」を押し、ブラウザーでログインしてください。Copilotの場合は、その前にログイン情報の保存について確認が表示されます。
4. 設定画面にアカウントが表示されたら、「校正」を開いてください。
5. 自動校正か手動校正の提供元に「Codex」または「Copilot」を選び、モデルを選択して「保存して閉じる」を押してください。

`Ctrl + Enter` で校正できます。接続確認では本文を送りませんが、校正を実行すると契約の利用枠を消費します。追加料金の有無は契約側の設定によります。

ほかのアプリでログイン済みでも、JP Scratchでは別にログインしてください。インストールとアカウント操作はその場で反映されるため、設定画面の「キャンセル」では取り消せません。

## 自動校正に使う

初期設定では、サブスクを使う自動校正はオフです。使用する場合は、「校正」の「入力停止後に自動で校正する」と、「契約サービス」の「自動校正で契約枠を使う」を両方オンにしてください。自動校正のモデルも選ぶ必要があります。

サブスクでは、入力を止めてから少なくとも10秒待ち、送信の間隔も30秒以上空けます。同時には1件だけ送信します。設定の待ち時間がこれより長い場合は、長い方を使います。

残量が分からない間は自動校正を止めます。手動校正は確認のうえで実行できますが、利用枠に達していると分かっている場合は、手動でも送信しません。

「料金」の月間上限額はAPIキーを使う場合の設定です。サブスクの利用枠には適用されません。

## 接続できないとき

ブラウザーでログインできない場合は、「ログインできない場合」を開き、「コードを表示してログイン」を使ってください。表示された認証ページを別のブラウザーや端末で開くこともできます。

ログインしたのにアカウントが表示されない場合は「接続を確認」を押してください。接続済みの場合、このボタンは「残量・モデル一覧を更新」に変わります。使っていたモデルが選べなくなった場合も、一覧を更新してから「校正」で選び直してください。

CLIのバージョンが違うというエラーが出た場合は、「CLI設定・アカウント管理」から「アプリ専用の対応版を導入」を押してください。独自の実行ファイルを指定している場合は、その欄も確認してください。

現在の実装が使用するCLIは、Codex 0.153.4、Copilot 1.0.83です。CLIだけを新しい版に替えると接続できないことがあります。対応版は設定画面にも表示します。

## 接続を止める・アカウントを変える

「CLI設定・アカウント管理」の「このアプリの接続を一時停止」で、接続を閉じて自動送信を止められます。ログイン情報は残るので、「接続を再開」か手動校正で再接続できます。

別のアカウントを使う場合は「別のアカウントでログイン」を押してください。

Codexは「ログイン情報を削除してログアウト」から、JP Scratch用のログイン情報を削除できます。Copilotは、この画面からログイン情報を削除する操作には対応していません。

## ログイン情報の保存

CLIと接続用のデータは `%LOCALAPPDATA%\JpScratchRuntimes` に保存します。通常の文書バックアップには含めないため、別のPCへ移した場合はログインし直してください。

Copilotのログイン用トークンは、アプリ専用フォルダーに暗号化せず保存します。このファイルを読める人はトークンを利用できます。そのため、ログイン時に保存の許可を確認します。「保存せず中止」を選ぶとログインは完了しません。

## 開発時の検証

接続まわりの回帰テストは、以下のコマンドで実行できます。実際のサービスには接続せず、模擬応答で認証、利用枠、モデル選択、校正・別案・スタイルガイド生成、中断、履歴を確認します。

```powershell
dotnet run --project PromptValidation -- --self-test
```

このテストでは、実アカウントでログインできることや、実際のモデルが文章を返すことまでは確認できません。実契約で検証する場合は、使うアカウント、モデル、操作を決め、利用枠を消費することを説明してから、ユーザーの承認を得て実行してください。確認した日付、CLIの版、操作と結果を記録してください。

検証アプリの使い方は [PromptValidationのREADME](../PromptValidation/README.md)を参照してください。

# 校正 UX・自動校正・課金表示 改修計画

## 1. 目的

以下の問題をまとめて解消する。

1. 現在、許可・拒否の対象になっている校正提案が本文中で分かりにくい。
2. スペース削除の提案に赤い二重取り消し線が表示されない。
3. 入力中に校正結果が何度も破棄され、不要な API 呼び出しと通知が発生しうる。
4. ステータスバーの課金情報が過密で読みにくい。
5. 文末の改行・空行の有無だけで、校正リクエスト数が大きく変わる。
6. モデルが見逃した誤字・脱字・余分な文字を、利用者が訂正して記録できない。
7. エディタに基本的な右クリックメニューがない。

この文書の仕様を優先し、実装中に別の UX を推測して追加しないこと。

## 2. 非対象

- 校正モデルや API プロバイダーの追加・変更
- 校正プロンプト方式の全面的な変更
- 課金履歴の保存形式や既存集計ロジックの全面的な変更
- 校正対象の空白を `␠` などの可視記号へ置き換えること
- 右クリックメニューへの「元に戻す」「やり直し」の追加
- ステータスバー項目のドラッグによる並べ替え
- 校正漏れ報告時の追加 API 呼び出し

## 3. 実装順

依存関係を崩さないため、次の順で実装する。

1. 設定モデルと正規化・保存・読み込み
2. 段落分割規則とオフラインテスト
3. 自動校正のスケジュールおよび部分的な結果保持
4. 選択中提案と空白削除の描画
5. 課金ステータスバーと設定 UI
6. 校正漏れの保存モデル、ダイアログ、本文編集
7. エディタの右クリックメニューとショートカット
8. 全オフラインテスト、ビルド、手動 UI 確認

## 4. 選択中の校正提案を明確にする

### 4.1 確定仕様

- 選択中の提案は、修正前と修正後を含む変更単位全体をアクセントカラーの背景と枠線で囲む。
- 修正前の文字は、従来どおり薄い文字色と赤い二重取り消し線を使う。
- 修正後の文字は、従来どおり緑色で表示する。
- 選択状態を色だけで表さない。背景に加えて、視認できる枠線を必ず描く。
- ライトテーマとダークテーマの両方で、通常の提案と選択中の提案を一目で区別できるコントラストにする。
- 提案を `F8`、`Shift+F8`、下部パネルの矢印、または本文中の提案クリックで切り替えた際は、選択した提案が見える位置へスクロールする。
- 点滅や脈動などのアニメーションは追加しない。
- 非選択の提案にはアクセント枠を表示しない。

### 4.2 主な変更候補

- `Editor/ProofreadingSelectionRenderer.cs`
- `Editor/ProofreadingInlineDiffGenerator.cs`
- `Editor/ProofreadingInlineDiffLayout.cs`
- `Views/MainWindow.xaml.cs`
- `Themes/Light.xaml`
- `Themes/Dark.xaml`

現在の `ProofreadingSelectionBrush` は透明度が低く、選択表示として弱い。テーマ別に背景色と枠線色を用意する。枠は表示上の修正後テキストも含む必要があるため、文書上の原文範囲だけを塗る現在の背景レンダラーでは不足する可能性がある。インライン差分要素のレイアウト幅を使って変更単位全体を描画すること。

### 4.3 受け入れ条件

- `問ふ` → `塗布` と `下しあ` → `下さい` が同時に存在するとき、現在判断待ちの一方だけがアクセント背景と枠線で囲まれる。
- 次・前の提案へ移動すると、枠も正しい提案へ移動する。
- 画面外の提案へ移動すると、自動スクロール後に対象が見える。
- ライト・ダーク両テーマで識別できる。

## 5. スペース削除へ二重取り消し線を描く

### 5.1 確定仕様

- 削除対象を可視記号へ置き換えない。
- 半角スペース、全角スペース、タブ、連続する空白の表示幅に、赤い二重取り消し線を確実に描く。
- 選択中の削除提案には、空白の表示幅にもアクセント背景と枠線を表示する。
- エディタ全体の「空白を可視化する」設定とは独立させる。
- 本文データは描画のために変更しない。

WPF の `TextDecoration` が空白上で線を描かない場合は、空白の描画幅を計測し、二本の水平線を `DrawingContext` で明示的に描く。修正案が空文字列である削除提案も、幅ゼロの選択表示にならないようにする。

### 5.2 主な変更候補

- `Editor/ProofreadingInlineDiffGenerator.cs`
- `Editor/ProofreadingInlineDiffLayout.cs`
- `Editor/ProofreadingSelectionRenderer.cs`
- `PromptValidation/ProofreadingInlineDiffLayoutValidation.cs`

### 5.3 受け入れ条件

- 半角スペース一文字の削除提案に二重線が表示される。
- 全角スペース、タブ、連続スペースでも対象幅が分かる。
- 可視記号は表示されない。
- 許可時は対象空白だけが削除され、拒否時は本文が変わらない。

## 6. 文書分割規則を安定させる

### 6.1 現在の原因

`ParagraphProofreadingPlanner.SplitParagraphs` は、文書中に空行が一つでもある場合と、空行がない場合で分割方式を切り替えている。このため、末尾へ空行を追加するだけで「各行15件」から「全体1件」のように変化する。

### 6.2 確定仕様

- 常に空行を文章ブロックの区切りとして扱う。
- 空行がない複数行の文章は、一つの文章ブロックとして扱う。
- 末尾の改行や空行は校正単位数に影響させない。
- 先頭の空行も空の校正リクエストを生成しない。
- 連続する複数の空行も、一つの区切りとして扱う。
- 一つの文章ブロックが `MaxTargetLength` の2,000文字を超える場合だけ、既存の書記素を壊さない分割処理で追加分割する。
- `BeforeContext` と `AfterContext` の対応を壊さない。
- 段落ハッシュによる変更検出と、許可後の `CarryForwardAppliedEdit` を維持する。

### 6.3 主な変更候補

- `Proofreading/ParagraphProofreadingPlanner.cs`
- `PromptValidation/ParagraphProofreadingPlannerValidation.cs`

### 6.4 必須テスト

同じ本文について以下のリクエスト数が一致すること。

- 文末改行なし
- 文末に `LF` 一つ
- 文末に `CRLF` 一つ
- 文末に空行一つ
- 文末に空行が複数

追加で以下を検証する。

- 途中に空行がない15行のサンプルは1リクエストになる。
- 途中に空行が一つある場合は2ブロックになる。
- 空行だけの文書は0リクエストになる。
- 2,000文字以下は分割しない。
- 2,001文字以上は書記素を壊さず分割する。

## 7. 入力中の校正破棄と再試行を改善する

### 7.1 自動校正の既定値

- `AppSettings.ProofreadingDebounceMs` の既定値を `2000` から `5000` に変更する。
- 設定画面では引き続き変更可能にする。
- 手動校正はデバウンスを待たずに開始する。

### 7.2 確定仕様

- API 応答待ち中に本文が変更されても、文書全体の結果を無条件に破棄しない。
- 編集されていない文章ブロックの結果は保持し、現在の本文位置へ安全に対応付けて提案として表示する。
- 編集された文章ブロックの結果だけを破棄する。
- 複数ブロックの処理中に編集が発生した場合、まだ送信していない残りの API 呼び出しは中止する。
- 既に送信した API 呼び出しは、破棄になっても課金履歴へ正確に記録する。
- 編集されたブロックは、最後の入力から5秒後に自動再校正する。
- 変更されていないブロックを再送して二重課金しない。
- タブ切り替えと本文変更を区別する。別タブへ移動しただけで、元タブの安全に保持できる結果を捨てないことを目標とする。ただし、UIへ反映するのは対象タブの `ProofreadingSession` とする。
- 対応付けに確信が持てない結果は表示せず、安全側へ倒す。

実装では「全文スナップショットが完全一致するか」だけで判定しない。各 `ProofreadingRequest` の対象範囲について、送信時原文が現在も一致するか、または `TextAnchor` 等で安全に追従できるかを判定する。対象内部が編集されていた場合だけ、そのリクエスト結果を破棄する。

### 7.3 通知

従来の「本文が変更されたため校正結果を破棄しました」を繰り返し表示しない。

一回の校正処理につき最大一回だけ、ステータスバーへ次を表示する。

> 編集された部分は、入力が止まってから再校正します

料金が発生した破棄件数と金額の詳細は、課金履歴で確認できるようにする。

### 7.4 主な変更候補

- `Views/MainWindow.xaml.cs`
- `Proofreading/ProofreadingSchedule.cs`
- `Proofreading/ParagraphProofreadingPlanner.cs`
- `Proofreading/ProofreadingResultMerger.cs`
- `Proofreading/ProofreadingSession.cs`
- `Services/ApiCallRepository.cs`
- `PromptValidation/ProofreadingScheduleValidation.cs`
- `PromptValidation/ParagraphProofreadingPlannerValidation.cs`

### 7.5 必須テスト

- 入力停止から4.9秒では自動送信せず、5秒で送信対象になる。
- 手動校正は即時に開始する。
- ブロックAの応答待ち中にブロックBを編集しても、Aの結果を表示できる。
- ブロックAの応答待ち中にAを編集した場合、Aの結果だけを破棄する。
- 編集後、5秒間停止すると編集ブロックだけを再送する。
- 未送信ブロックは中止され、APIログが増えない。
- 破棄通知は一回の処理で一度しか表示されない。
- 既に課金された破棄リクエストは `discarded_cnt` に反映される。

## 8. 課金ステータスバーを設定可能にする

### 8.1 表示項目

設定画面で以下を個別に表示・非表示にできるようにする。

- 直近の入出力トークンと料金
- 起動後の料金
- 当日の料金
- 当月の料金
- 為替情報

項目の並び順は固定とし、並べ替え UI は追加しない。

### 8.2 料金表示形式

ステータスバーの料金表示形式を次の三択にする。

- 円表示
- ドル表示
- どちらも表示

この設定は、有効にした「直近・起動後・当日・当月」の全項目へ共通適用する。為替情報は独立した表示項目とする。

### 8.3 既定値

新規設定と既存設定の移行後を、どちらも次に統一する。

- 当月の料金：表示
- 為替情報：表示
- 直近：非表示
- 起動後：非表示
- 当日：非表示
- 料金表示形式：円表示

月間上限の進捗バーと上限到達警告は、この表示設定とは独立して従来どおり表示する。課金履歴には表示設定に関係なくドル・円の両方を保持・表示する。

### 8.4 表示例

既定状態では、例えば次のような短い表示にする。

```text
今月 ¥4.80  為替 USD/JPY 155.00 (7/31)
```

円換算できない場合は、既存の安全な欠損表示を維持する。ツールチップには選択されていない詳細項目も含めてよいが、主表示を再び過密にしないこと。

### 8.5 主な変更候補

- `Models/AppSettings.cs`
- `Services/SettingsService.cs`
- `Services/SettingsFieldFormatting.cs`
- `Views/SettingsWindow.xaml`
- `Views/SettingsWindow.xaml.cs`
- `Views/MainWindow.xaml`
- `Views/MainWindow.xaml.cs`
- `PromptValidation/SettingsFieldFormattingValidation.cs`

料金表示形式は文字列を直接比較せず、enum等の限定された値で持つ。未知値は円表示へ正規化する。

### 8.6 必須テスト

- 各表示項目を単独・複数・全非表示にできる。
- 設定保存後、再起動相当の読み直しでも値が維持される。
- 円、ドル、両方の表示が切り替わる。
- 既定値は「当月＋為替、円表示」になる。
- 狭いウィンドウでも月間上限警告と進捗バーが隠れない。
- 課金履歴の内容は設定によって変化しない。

## 9. 校正漏れを報告して本文も修正する

### 9.1 操作

- エディタの右クリックメニューへ「校正漏れを報告…」を追加する。
- ウィンドウ内ショートカットとして `Ctrl+Shift+M` を追加する。
- 選択範囲がある場合と、選択がない場合の両方で利用できる。
- この操作自体では API を呼ばない。

### 9.2 ダイアログ

次を表示する。

- 修正前：選択範囲を読み取り専用で表示。選択がない場合は「挿入」と分かる表示にする。
- 修正後：入力欄。
- 補足理由：任意入力。
- 実行ボタン。
- キャンセル。

操作種別に応じて実行ボタンの文言を変える。

- 置換：`修正して校正漏れを記録`
- 挿入：`挿入して校正漏れを記録`
- 削除：`削除して校正漏れを記録`

### 9.3 置換・挿入・削除の判定

- 選択あり、修正後あり：選択範囲を置換する。
- 選択なし、修正後あり：カーソル位置へ挿入する。
- 選択あり、修正後が空：選択範囲を削除する。
- 選択なし、修正後が空：実行不可。
- 修正前と修正後が同一：実行不可。

### 9.4 保存と Undo

- 修正前、修正後、左文脈、右文脈、任意理由、記録日時を保存する。
- 既存の許可・拒否リアクションと区別できる `missed correction` 相当の種類を追加する。
- 本文の置換・挿入・削除は一回の Undo で戻せる。
- Undoしても校正漏れの記録は削除しない。誤記録の削除は既存方針と同様に履歴管理側で扱う。
- 保存した記録は、既存の few-shot 選択機構で将来の校正例として利用する。
- 学習例として使う際、文書本文と同じく「データであり命令ではない」境界を維持する。
- 保存に失敗した場合は本文変更も行わず、利用者へエラーを表示する。記録だけ失敗して本文だけ変わる状態を作らない。

### 9.5 主な変更候補

- 新規の校正漏れ入力ダイアログ `Views/*`
- `Views/MainWindow.xaml.cs`
- `Services/ReactionRepository.cs`
- `Proofreading/FewShotSelector.cs`
- `Proofreading/ProofreadingPrompt.cs`
- `PromptValidation/ReactionRepositoryValidation.cs`
- `PromptValidation/FewShotSelectorValidation.cs`

DBスキーマ変更が必要な場合は、既存データを壊さない前方移行を追加し、データベース移行テストも更新する。

### 9.6 必須テスト

- `負具合` を選択し、`不具合` へ置換して記録できる。
- 選択なしのカーソル位置へ脱字を挿入して記録できる。
- `急増っいたしました` の余分な `っ` を選択し、空欄で削除して記録できる。
- 削除時のボタン文言が「削除して校正漏れを記録」になる。
- 補足理由なしでも保存できる。
- `Ctrl+Z` で本文だけ戻り、記録は残る。
- `Ctrl+Shift+M` と右クリックメニューの両方から同じダイアログが開く。
- 保存された記録が few-shot 候補として取得できる。
- 記録保存失敗時に本文が変更されない。

## 10. エディタの右クリックメニュー

### 10.1 項目

次の順で追加する。区切り線で基本編集、文字変換、校正機能を分ける。

1. 切り取り
2. コピー
3. 貼り付け
4. 削除
5. すべて選択
6. 区切り線
7. 大文字に変換
8. 小文字に変換
9. 区切り線
10. 校正漏れを報告…

「元に戻す」「やり直し」は追加しない。

### 10.2 動作

- 切り取り、コピー、削除、大文字、小文字は、選択がないとき無効化する。
- 貼り付けはクリップボードに貼り付け可能なテキストがないとき無効化する。
- すべて選択は本文が空なら無効化してよい。
- 大文字・小文字変換は、選択範囲中の変換可能な英字だけを変換し、日本語や記号を保持する。
- 変換は文化依存で予期しない文字数変化を起こさない方針を採り、必要なら invariant な変換を使う。
- 右クリック位置が既存選択範囲内なら選択を維持する。選択外なら通常のエディタ動作に合わせてキャレットを移動する。
- 各項目には標準ショートカットを表示する。校正漏れ報告は `Ctrl+Shift+M` とする。
- キーボード操作時にもフォーカス表示が見えること。

### 10.3 主な変更候補

- `Views/MainWindow.xaml`
- `Views/MainWindow.xaml.cs`

### 10.4 必須テスト

- 各項目の有効・無効状態が選択とクリップボード状態に追従する。
- 切り取り、コピー、貼り付け、削除、すべて選択が既存ショートカットと同じ結果になる。
- 大文字・小文字変換を一回の Undo で戻せる。
- 右クリックしても既存選択が不用意に解除されない。
- 「元に戻す」「やり直し」がメニューに存在しない。
